# Evidence-lane starvation repair
The morning audit found that bootstrap and Ollama residency blocked every portfolio lane, including verified receipt replay and source-prerequisite planning. The service also skipped the entire portfolio during bootstrap. The repair restricts busy execution to the two non-inference evidence lanes, retains the 1.5GB available-RAM admission and 6GB free-disk reserve, respects per-lane cooldown and existing portfolio/qualification locks, and treats an unavailable or malformed Ollama status response as busy. During bootstrap the service dispatches evidence-only work when source knowledge is ready, not competing model inference. No new model calls or weight updates are credited to evidence replay. Actual service activation is separate from source verification.
