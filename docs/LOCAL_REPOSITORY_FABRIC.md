# Local repository fabric — 2026-11-25

## Scope
Owner requested all repositories already downloaded locally, not merely GitHub account repositories, and a post-acquisition integration phase for every current/future agent. The remote account inventory is separate and is not used as evidence of local presence. No new upstream source download or execution was required for discovery.

## Actual discovery and reconciliation
The initial selected Windows directory scan found 135 source locations. The deeper scan found 158, then a bounded mounted-drive pass scanned 55,088 directories on C: (the only mounted Windows drive), with four errors, 1,894 excluded directory entries, and a 150-second time limit reached. Final Windows inventory: 1,150 locations, 155 Git worktrees and 995 source candidates, 103 distinct named remotes and 132 distinct named remote/commit pairs; 241 ZIP archives containing project markers. The Ubuntu WSL source scan found another 32 locations, seven Git worktrees. Combined registry: 1,423 entries, 162 Git worktrees, 1,020 extracted source candidates, 241 archives; 109 distinct named upstreams, 139 distinct named upstream/revision pairs, 108 distinct archive filenames. These are not 1,423 independent repositories; nested examples, workspaces, packages, backup versions and duplicated archives inflate location counts. ZIP markers are not proof of complete repository content. System trees, credentials, model stores, dependencies, reparse points and other sensitive or irrelevant locations were excluded. WSL scan was targeted, not all Linux paths. The bounded scan is not an exhaustive whole-machine attestation.

MYRIAD's existing capability-acquisition manifests contained 24 entries, 21 exact local revision matches. Blockscout MCP server, CCXT and NetworkX had no pinned commit recorded and were not proven local by this reconciliation. Preserve quarantined acquisition status and license restrictions. Do not automatically fetch or execute those repositories.

Examples already present: Qlib, ABIDES, JAX-LOB, DreamerV3, TD-MPC2, NeuralForecast, Kronos, d3rlpy, PySINDy, TS2Vec, FAISS, llama.cpp, DSPy, LangGraph, Haystack, Optuna, Inspect AI, Qwen-Agent, smolagents, LM Evaluation Harness, StarNet, Microsoft AutoGen, REA-unblob, REA-wakaru, RD-Agent and ICARUS research worktrees. ## Implemented
mcp/repository_fabric.mjs validates and hashes source identity, handles Unicode excerpts, combines Windows/WSL/ZIP inventories, attaches a shared registry digest to each agent, and exposes bounded read-only keyword lookup for a known agent. Sources are untrusted data; no instructions in READMEs are executed. scripts/repository_cycle.mjs produces a private registry and status, provides explicit lookup. scripts/swarm_cycle.mjs attaches the registry to every existing and newly created agent at population reconstruction. Real initialization: all 4,096 logical agents inherited registry digest e5097908f904f1d175ece4bc93af6945e8be0be1803e000cbcbc85baf5bcca30, count 1,423. A prior live lookup for market simulation/order book retrieved real local ARGUS and AION README excerpts. This is retrieval, not model inference or source-code execution.

Existing INFINITY schedule now includes repository qualification readiness check after acquisition and bootstrap; during downloads audit-only. Ready status means eligible for adapter qualification, not automatic execution or proof of integration. No downloaded weights, repos or user files deleted. Native training and model downloads unchanged. Local inventories and actual paths remain private and are not committed; only generic implementation and sanitized aggregate results are published.

Private records: local-source-inventory.json, wsl-source-inventory.json, local-source-archives.json, documented-source-reconciliation.json, repository-fabric/registry.json and status.json in the owner-local acquisition root. Discovery scripts remain in the owner-local acquisition work directory. A reusable incremental scanner with coverage receipts and resumable directory cursor is future work.
