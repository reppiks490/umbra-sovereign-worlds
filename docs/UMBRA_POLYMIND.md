# UMBRA Ω POLYMIND

Owner-authorized local expansion stacked on #29. Acquisition uses Ollama manifest inventory and Hugging Face pinned ONNX bundles from approved publishers including the ONNX Model Zoo. No remote code, pickle, training, paid inference or external model authority. The target is 100 total distinct weight artifacts; cross-format semantic deduplication is not guaranteed. One compact ONNX bundle per repository; explicit permissive license metadata, exact source commit, LFS SHA-256 and sizes, fixed approved file types, per-file disk checks, 180 MiB weight cap, 3 GiB reserve plus 256 MiB margin. Downloaded bundles are not automatically trained or inference-qualified. Catalog stays private.

Install an isolated Python 3.11 venv with binary wheels for onnxruntime, tokenizers and pillow. Use the reviewed checkout, run `python -m unittest discover -s tests -p test_polymind_acquire.py`. `python scripts/polymind_acquire.py --root <private-directory> --target 100` acquires, `--inventory` enumerates receipts. `scripts/polymind_infer.py --root <private-directory> --model <catalog-repo>` accepts bounded numeric synthetic evidence on stdin, verifies weight digest and RAM before a local CPU forward pass. Text encoder inputs only; outputs are shapes and digests, not scientifically qualified predictions. Vision/audio weights can be downloaded but require task-specific preprocessing/qualification. No deployment, automatic training or modification of existing schedules. Other runtimes (llama.cpp, OpenVINO, TensorFlow Lite) remain separate future integration lanes; no claim they were installed. Do not run competing acquisition queues on the same storage volume.
## Unified owner-local router

Set `UMBRA_POLYMIND_PYTHON` and `UMBRA_POLYMIND_ROOT` to the reviewed operator-owned absolute Python executable and private model catalog directory. `mcp/owner_once.mjs` accepts `{"operation":"polymind_list"}` and `{"operation":"polymind","arguments":{"runtime":"onnxruntime","model":"Xenova/all-MiniLM-L12-v2","role":"retrieval","seed":42,"steps":2}}`. Select only a discovered model/role pair; `runtime:"ollama"` delegates to the existing local role adapter. The router obtains actual deterministic numeric evidence and validates each returned model identity, revision, weight and output fingerprint. Gemma 3 12B is registered as a senior reasoning/research/critique candidate; download and sufficient free RAM are independent gates. No cross-runtime semantic mastery, autonomous engine decisions, new training or public hosting. Catalog-only vision/audio entries advertise no executable text role.

## Resource admission planner

The owner CLI accepts `{"operation":"polymind_plan","arguments":{"role":"reasoning"}}`. Read-only discovery returns resource-eligible and blocked candidates ordered by estimated RAM, not quality. Ollama requires weight size plus 1 GiB, or 2 GiB for weights at least 6 GiB; ONNX requires four times bundle size plus 1 GiB. Busy Ollama candidates are blocked. This is not a reservation, guarantee, benchmark or model training; recheck resources at dispatch. Mistral NeMo 12B, its q3_K_M variant and Mistral latest are registered as reasoning/research/critique candidates; installation is not implied.

## Explicit owner storage policy

Default acquisition remains 3072 MiB free plus 256 MiB headroom. An explicit owner override is `--minimum-free-mib 1024 --headroom-mib 756` (combined 1780 MiB), applied at bundle admission and each streamed write. This low reserve is unsuitable as a general Windows recommendation; system paging or concurrent writers can still consume disk. Do not infer permission to use it for other devices or jobs. The owner-local priority large-model queue remains separate.
